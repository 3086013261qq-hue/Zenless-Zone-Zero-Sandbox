# 002｜蓝灯 / 绿灯分层与触发规范 v1.0

> **执行 004 方案修订：** 新正式卡无 MVU、脚本、状态栏、NSFW 选项；蓝绿灯直接以静态世界书条目实现，保留世界书自身触发与双重防递归，固定铃为佩洛伊斯寄宿者。

## 蓝灯（BLUE，常驻而精简）
- 仅容纳长期必需且稳定的根规则：新艾利都、空洞、以太、社会秩序、扮演边界等，具体条目数在精修后决定。
- 使用角色所在世界自然成立的叙述，不写“模型请遵守”之类的制作说明，不把施工单放进世界书。
- 蓝灯一次审查一条；逐条核实来源与冲突，确认后再展开该条绿灯。
- 未验证的原卡素材不得作为官方事实硬写；明确分类为“官方”“卡内改编”“待核”。

## 绿灯（GREEN，按需触发）
- 一个条目只承载一个可判定主题，沿用成熟咩咩全栈两层结构；关键词不宜过宽。
- 普通业务绿灯必须同时设置 `exclude_recursion=true` 与 `prevent_recursion=true`；分区标记单列测试，不以此理由省略业务防护。
- 原卡 707 条的旧 `use_regex=true` 只是历史来源信息；新卡优先使用普通字面关键词触发，不依赖正则脚本，也不保留旧运行时条件。特殊匹配仅在静态世界书引擎原生支持并通过测试时允许。
- 22 个活动单字触发词（如“铃”“哲”“雅”）需做误触发专项；法厄同与哲/铃之间的复合身份引用必须核对。
- 每条附：主题 / 归属蓝灯 / 原卡条目 ID / 触发键与匹配方式 / 双重防递归 / 正文来源级别 / QA 状态。
- 不直接复制原本前后 XML 分区条目；需保障全局分区界限、顺序与上下文插入位置配对。

## 与其他层的边界
- 人物资料放人物层；角色专属技能放能力层；特定事件放时间线；可到达场景放地点层。
- `story` 与 `lite story` 是同一事件的两个文本版本，先做映射与开关选择，不得同时激活；必须编写铃为寄宿者的唯一静态事件正文，不保留哲寄宿切换。
- 原卡 `optional` 与 `auxiliary` 逐项分流；停用脚本不得默认为已验证可用。

## 逐条 QA
1. 来源与卡内设定不矛盾；2. 字数与语义精简；3. 正则在目标 SillyTavern 真实匹配；4. 防递归双开；
5. 人物/能力与机制同源；6. 与相邻蓝绿灯不重复、不越界；7. 不导致分区标签错序；8. Android 实机抽检合格。
