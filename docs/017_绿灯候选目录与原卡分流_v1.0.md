## 三、避免重复注入的边界
- **BLUE-01 与 BLUE-08：** 旧文明背景、虚狩称号与城市经济生产分开；不把旧都主线事故全文搬入 BLUE-01。
- **BLUE-02 与 BLUE-04：** 空洞地貌、特殊裂隙与时效性「萝卜」分开；零号空洞、芭蕾双子等可到达地点留地点模块。
- **BLUE-03 与敌人/能力：** 以太适性、腐蚀、秽息是机制；特定以骸与牲鬼个体、招式、战斗状态属 mob/能力层。
- **BLUE-04 与 BLUE-07：** HIA 的调查许可流程和 HIA 的组织职能不是同一绿灯，不复制两遍完整机构介绍。
- **BLUE-05 与 BLUE-06：** 机器自我意识及邦布技术属于 05；智慧族群在城市共居属于 06。
- **BLUE-07 与 BLUE-08：** 白祇、TOPS、卡吕冬等组织独立描述归 07；产业链、材料与交易规则归 08。
- **BLUE-09 与人物/能力/时间线：** H.D.D./伊埃斯的协作机制可以绿灯展开；佩洛伊斯寄宿事件、铃治疗与觉感术的技能解锁、卡洛丝及哲铃的具体剧情，交后续人物、能力、时间线。**不能仅因 BLUE-09 常驻就让所有 NPC 在初始日期知道秘密。**

## 四、触发与结构验收契约

1. 拟稿时一条 GREEN 只写一个主题；沿用内生世界 `<设定:标题>`（最终标签与母版对齐后确定），不夹施工指令。
2. **普通字面触发优先：** 不用旧脚本或世界书正则扩展；仅在引擎原生 `use_regex` 经真实 QA 后才可个别使用。建议关键词仅为候选，**不保证实测已无误触发**。
3. 正式绿灯设置 `constant=false`、`selective=true`、`use_regex=false`、`extensions.exclude_recursion=true` 与 `extensions.prevent_recursion=true`；两项防递归不省略。
4. 避免单字触发 `铃`、`哲`、`雅`、`以`、`洞`，也不以泛词 `以太`、`邦布`、`空洞` 作全组通用键。当前 GREEN 的关键字须待逐条触发测试再正式确认。
5. 同一来源被多处参考，不等于两处可以重复全文；最终 QA 检查触发交叉及相互套娃、同名复条与时间线开关。
6. 涉及原卡旧 `getvar`/EJS 的来源不得原文迁入；属于原卡不同游戏版本或寄宿分支时改为单一铃路线，相关剧情前的条目不开。
7. 不把任何绿灯目录候选自动升格为“官方真相”；每条需 `OFFICIAL_CHECKED` / `CARD_ADAPTATION` / `HOLD` 等来源级别核准。
8. 地点仍独立于九条世界观蓝灯：**只有一条 LOCATION-BLUE-00 总分区蓝灯**，地点细条由地点模块做；当前 GREEN 不提前扩展地图。
